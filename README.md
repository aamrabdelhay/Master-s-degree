# دبلومة القانون الخاص — جامعة العاصمة | جدول الامتحانات النهائية

موقع جدول امتحانات نهائية لدبلومة القانون الخاص (سنة واحدة)، مبني بـ **Next.js + TypeScript**
بنفس تصميم الملف المرجعي (Senior Year — Final Examination Schedule 2026)، مع صفحة أدمن
كاملة تقدر منها تعدّل كل حاجة من غير ما تلمس الكود، والبيانات بتتخزن في قاعدة بيانات
مشتركة (Redis) فالتعديلات بتظهر لكل الزوار فوراً.

## المميزات

**الصفحة العامة `/`**

- تصميم مطابق للمرجع: نفس الألوان (`#0f172a` / `#c5a059` / خلفية `#f1f5f9`)، نفس الخطوط
  (Amiri للعربي، Cinzel للعناوين، Cairo، Playfair Display)، نفس الهيدر بالـ gradient
  والـ clip-path، نفس الكروت الزجاجية `glass card`، نفس التايمر، نفس صفوف الأسئلة
  `q-row` بدائرة الرقم الذهبية وتأثير الـ hover، وميزان ⚖ متحرك في الخلفية وتأثير AOS.
- الاتجاه RTL بالكامل، وموبايل أولاً (responsive).
- بدون أي شعارات، وبدون تعليمات أدمن ظاهرة.
- صفحة واحدة فقط (مفيش اختيار فرقة) — الدبلومة سنة واحدة.
- كل مادة كارت فيه: الاسم، التايمر، شارة «شكل الامتحان والمقرر»، «وصلنا لحد فين»
  (مخفي لحد ما يتكتب)، «الأسئلة المحددة» (مجموعات مرقّمة)، شارة «الملغي» (اختيارية)،
  وزرار «📖 الكتاب».
- **التايمر:** قبل تحديد الموعد بيكتب «الموعد لم يُحدد بعد»، وبعد ما تحدد الموعد بيعد
  تنازلياً (يوم/ساعة/دقيقة/ثانية)، وبعد بداية الامتحان بيكتب **EXAM STARTED**.
- **الترتيب التلقائي:** المواد اللي ليها موعد بتظهر الأقرب أولاً، والمواد اللي لسه ملهاش
  موعد بتظهر في الآخر بالترتيب اليدوي. المواد المنتهية بتفضل ظاهرة مع علامة **انتهى**.
- **توقيت القاهرة دائماً:** التحويل بيحصل على السيرفر باستخدام قاعدة `Africa/Cairo`
  (بما فيها التوقيت الصيفي)، فالعد التنازلي واحد لكل الزوار مهما كان توقيت جهازهم.

**صفحة الأدمن `/admin`**

- أول مرة: شاشة «اختر كلمة المرور» (حقلين + حد أدنى 8 حروف) — وبعد الحفظ مفيش إنشاء
  باسورد تاني.
- كلمة المرور متخزنة **scrypt** (مش نص صريح)، والجلسة `cookie` بـ
  `httpOnly + secure + sameSite=strict`، مع حد أقصى **5 محاولات دخول غلط** (قفل 15 دقيقة).
- تعديل عنوان الهيدر والعنوان الفرعي.
- لكل مادة: الاسم، التاريخ والوقت، شكل الامتحان، المقرر، «وصلنا لحد فين»، الأسئلة المحددة
  (إضافة/تعديل/حذف/إعادة ترتيب — مجموعات لكل واحدة عنوان)، الملغي، لينك الكتاب.
- إضافة مادة / حذف مادة / إعادة ترتيب المواد يدوياً.
- تغيير كلمة المرور.
- زرار «حفظ التغييرات» + رسالة تأكيد، والتغييرات تظهر لكل الزوار فوراً.
- تصميم نظيف بنفس ألوان الموقع ويشتغل من الموبايل.
- الصفحة العامة مفيهاش أي لينك ظاهر للأدمن — بتفتحها بكتابة `/admin` في آخر اللينك.

## التشغيل محلياً

```bash
npm install
npm run dev
```

- الصفحة العامة: <http://localhost:3000>
- صفحة الأدمن: <http://localhost:3000/admin>

من غير أي متغيرات بيئة، التخزين بيشتغل **في الذاكرة** (مناسب للتجربة فقط، البيانات
بتضيع مع إعادة تشغيل السيرفر). عشان تجرب التخزين الحقيقي محلياً، اعمل ملف `.env.local`
وحط فيه بيانات Upstash (شوف تحت).

```bash
npm run build   # بناء للإنتاج
npm start       # تشغيل نسخة الإنتاج
```

## متغيرات البيئة

| المتغير | مطلوب؟ | الوصف |
| --- | --- | --- |
| `KV_REST_API_URL` | ✅ (في الإنتاج) | رابط REST لقاعدة بيانات Redis |
| `KV_REST_API_TOKEN` | ✅ (في الإنتاج) | توكن الكتابة/القراءة |
| `UPSTASH_REDIS_REST_URL` | بديل | نفس القيمة لو بتستخدم Upstash مباشرة |
| `UPSTASH_REDIS_REST_TOKEN` | بديل | نفس القيمة |
| `ADMIN_SESSION_SECRET` | اختياري | سر إضافي لتوقيع جلسة الأدمن (أي نص طويل عشوائي) |

الكود بيقرأ الأسماء دي تلقائياً، فمش محتاج تعدّل أي ملف.

> لو المتغيرات مش موجودة في Vercel، الموقع هيفضل شغال بالبيانات الافتراضية، بس أي تعديل
> من الأدمن مش هيضمن إنه يفضل محفوظ. اربط قاعدة البيانات الأول.

## النشر على GitHub + Vercel خطوة بخطوة

### 1) رفع الكود على GitHub

```bash
git init
git add .
git commit -m "Final exam schedule — Law Diploma (Capital University)"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

(بدّل `USERNAME/REPO` باسم حسابك واسم الريبو.)

### 2) ربط الريبو بـ Vercel

1. ادخل على <https://vercel.com> وسجّل دخول بحساب GitHub.
2. من الداشبورد: **Add New… → Project**.
3. اختار الريبو اللي رفعته، واضغط **Import**.
4. Vercel هيتعرّف تلقائياً على إنه مشروع Next.js — **متغيّرش** أي إعداد
   (Framework Preset: Next.js، Build Command: `next build`، Output: `.next`).
5. متضغطش Deploy لسه — الأول ضيف متغيرات البيئة (الخطوة 3).

### 3) إضافة متغيرات البيئة

**Settings → Environment Variables** وضيف:

| Key | Value |
| --- | --- |
| `KV_REST_API_URL` | الرابط من Upstash (شوف القسم اللي تحت) |
| `KV_REST_API_TOKEN` | التوكن من Upstash |
| `ADMIN_SESSION_SECRET` | (اختياري) نص عشوائي طويل |

اختار **Production + Preview + Development** لكل واحد، وبعدين **Save**.

### 4) النشر

اضغط **Deploy** (أو **Redeploy** لو كنت عملت Deploy قبل إضافة المتغيرات — لازم redeploy
عشان المتغيرات تتحمّل).

بعد ما يخلص هتلاقي لينك زي `https://your-project.vercel.app`.

### 5) أول دخول للأدمن

1. افتح `https://your-project.vercel.app/admin`.
2. هتلاقي شاشة **«اختر كلمة المرور»** — اكتب باسورد (8 حروف على الأقل) وأكده، واضغط حفظ.
3. هتدخل لوحة التحكم على طول. الباسورد اتسجل، ومش هينفع حد يعمل باسورد تاني.

### 6) أي تعديل بعد كده

من لوحة التحكم، وبعد ما تضغط **حفظ التغييرات**، التغييرات بتبان لكل الزوار فوراً
(الصفحة بتقرأ من الداتابيز في كل زيارة).

## ربط قاعدة البيانات (Upstash / Vercel KV)

### الطريقة الأولى (الأسهل) — من داخل Vercel

1. من داشبورد Vercel: **Storage → Create Database**.
2. اختار **Upstash for Redis** (اسمها في السوق: Marketplace → Upstash Redis).
3. اختار اسم، ومنطقة قريبة (مثلاً `eu-central-1` أو `us-east-1`)، واضغط **Create**.
4. اضغط **Connect Project** واختار مشروعك.
5. Vercel هيضيف المتغيرات `KV_REST_API_URL` و `KV_REST_API_TOKEN` للـ Project تلقائياً.
6. اعمل **Redeploy** للمشروع.

> لو ظهرت أسماء مختلفة (مثلاً `UPSTASH_REDIS_REST_URL`)، الكود بيقراها برضه عادي.

### الطريقة الثانية — من موقع Upstash مباشرة

1. اعمل حساب على <https://upstash.com> (فيه باقة مجانية).
2. **Create Database** → اختار **Regional** ومنطقة قريبة.
3. من صفحة الداتابيز: تبويب **REST API** — هتلاقي:
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
4. ضيفهم في Vercel → **Settings → Environment Variables**، وبعدين اعمل **Redeploy**.

### التأكد إن الربط شغال

- افتح `/admin` — لو ظهر تنبيه أحمر «قاعدة البيانات المشتركة غير مربوطة»، معناها المتغيرات
  مش موجودة أو محتاجة Redeploy.
- أول زيارة للموقع بعد الربط بتزرع البيانات الافتراضية (المواد السبعة بالترتيب + لينك
  التليجرام) في قاعدة البيانات تلقائياً.
- كل البيانات متخزنة في مفتاح واحد اسمه `lawdiploma:site:v1`، وكلمة المرور في
  `lawdiploma:auth:v1`.

> **مهم:** أي بيانات موجودة في الذاكرة قبل الربط مش بتنقّل — بعد الربط التعديلات الجديدة
> هي اللي بتتخزن. عادي، هتضيفها من الأدمن مرة واحدة.

## استخدام صفحة الأدمن

- **المواعيد:** لكل مادة اختار التاريخ والوقت من حقل `datetime-local` — **بتوقيت القاهرة**
  (الحقل بيعرض معاينة للموعد بالعربي عشان تتأكد). لو الحقل فاضي، الكارت بيقول
  «الموعد لم يُحدد بعد».
- **الترتيب:** أزرار ▲ / ▼ في كل مادة بتحدد الترتيب اليدوي — وده اللي بيظهر للمواد اللي
  لسه ملهاش موعد. المواد اللي ليها موعد بتترتب تلقائياً بالأقرب أولاً.
- **الأسئلة المحددة:** اضغط «+ مجموعة أسئلة جديدة» لكل موضوع (مثلاً «أسئلة هامة جداً»)،
  وكل مجموعة فيها «+ إضافة سؤال». كل نقطة بتظهر في الموقع بدائرة رقم ذهبية زي المرجع.
  لو عنوان المجموعة فاضي، الموقع بيكتب «الأسئلة المحددة».
- **وصلنا لحد فين / الملغي:** أي حقل فاضي = القسم/الشارة مخفية تماماً في الموقع.
- **لينك الكتاب:** لكل مادة على حدة، والافتراضي لينك التليجرام
  `https://t.me/+R2FwAGsyjiBhYThk`.
- **الحفظ:** زرار «حفظ التغييرات» في الشريط السفلي (بيبان دايماً). لو فيه تغييرات مش
  متحفظة، الشريط بيحذّرك قبل ما تقفل الصفحة.
- **كلمة المرور:** من قسم «كلمة المرور» في آخر الصفحة (محتاج الباسورد الحالي).

## ملاحظات مهمة

- **مفيش أي لينك للأدمن في الصفحة العامة.** صفحة الأدمن سرية بلينكها `/admin`، و`noindex`
  عشان محركات البحث ما تفهرسهاش.
- **نسيت كلمة المرور؟** مفيش استرجاع تلقائي (مفيش إيميل). الحل: من داشبورد Upstash امسح
  المفتاح `lawdiploma:auth:v1` — الموقع هيرجع يطلب «اختر كلمة المرور» من جديد.
- **عايز ترجّع المواد الافتراضية؟** امسح المفتاح `lawdiploma:site:v1` من Upstash.
- **تغيير كلمة المرور بيلغي كل الجلسات القديمة** تلقائياً (بما فيها أي جهاز تاني).
- **الوقت:** أي تعديل في المواعيد بيتحسب بتوقيت القاهرة، حتى لو الزائر فاتح من أي دولة.
- **الخصوصية:** كل النصوص بتتخزن كـ JSON وبتتعرض عن طريق React (من غير HTML)، ووسوم HTML
  بتتشال قبل الحفظ.
